# App 崩溃测试约束

- 每个用例使用稳定 ID，明确故障类型、触发线程、前置条件、预期进程行为与证据来源。
- 未捕获异常、协程异常、Native crash、ANR、OOM 和主动进程终止分别验收；kill/exit 不能当成未捕获异常，主线程阻塞不能直接认定为已确认 ANR。
- 首期覆盖根入口及项目档案列出的常见异常场景，每种场景分别验证主线程与后台线程的未捕获行为。通过真实错误操作产生越界、空指针、类型转换、整数除零和解析异常；主动异常及参数/状态检查可显式抛出。
- 用户已授权 Native 对应版本及 abort/非法内存访问。Native 与 Java 故障语义分开：算术通过 raise(SIGFPE) 显式模拟，不使用 C++ 未定义除零行为冒充稳定故障；C++ 无 lateinit，使用受检 optional 访问模拟。每个 Native 场景一个独立 C++ 文件，不覆盖宿主信号或 terminate 处理器。
- JNI 注册边界 NativeBridge 保留名称，其余场景继续 R8 混淆。so 的导出、剥离符号、ABI 和 16 KB 对齐单独验收，设备通过范围不能从构建结果推断。
- 每个场景记录实际异常类与关键堆栈，不强制不同平台的集合/字符串实现抛出完全相同的异常子类；整数除零用运行时整数操作，不能以浮点除零代替。
- 每次运行只触发一个致命故障；App 崩溃后由外部测试工具重新启动，再执行下一项，不能在同一进程顺序触发全部故障。
- 库只提供显式入口，不自动触发、不默认接管或覆盖宿主 UncaughtExceptionHandler、不吞掉测试异常、不绑定采集 SDK。
- 测试宿主仅在主动调用后触发；OOM、长时间阻塞等用例单独确认。每次故障后核实状态与证据，禁止盲目循环触发；不默认开发演示页面。
- 使用现有或明确指定的测试宿主与模拟器，保护无关 App 和用户数据；不默认清数据、卸载或清空全设备日志。
- 触发前持久化用例 ID、运行 ID、版本与时间，触发后由外部 runner/adb 或重启后的检查获取证据，不能依赖已崩溃进程继续断言。
- 分别记录“故障触发”和“宿主采集”结果：前者核对预期堆栈、线程与进程行为，后者核对采集记录及关联 ID。未接入 SDK 或无法访问后台时，采集链路标为未验证。
- JVM 测试覆盖元数据、参数与非致命逻辑；实际故障使用设备证据，避免直接在单元测试或 instrumentation runner 所在进程执行致命故障。
- 报告记录设备/API、变体、命令、观察与证据；ANR、OOM 等受环境影响的用例不能承诺所有设备必现。
- release 保留库时检查宿主 R8 mapping 与最终 DEX，核实原始包名/类名改写；保留真实堆栈及 mapping。若宿主另选 debugImplementation，再验证正式包排除。不得把混淆或依赖声明当成最终产物验证。
- 预期故障不是待修复 Bug；错误类型、错误线程、无法触发、误触发与宿主干扰才按 Bug 流程处理。
